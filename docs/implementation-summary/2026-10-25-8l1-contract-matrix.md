# 8L1-HOST native 8B/8C contract-to-side-effect matrix (generation 3)

PR [#120](https://github.com/KaisAbiyyi/chat-on-steroids-on-steroids/pull/120), tracking [#114](https://github.com/KaisAbiyyi/chat-on-steroids-on-steroids/issues/114). This matrix compares the *accepted JavaScript contract* to the independently implemented *product-owned C#/Rust WebView2 authority*. It is **not** an assertion that the JavaScript controllers run in the native host. The C#/Rust implementation deliberately avoids starting Node or interpreting extension JS inside the privileged host. A static mapping is **review evidence, not proof of behavioral equivalence**; the named compiled policy tests, Rust regressions and owner-operated physical probes remain separately required.

## Source-bound verification and acceptance boundaries

- `.github/workflows/8l1-host.yml` compiles the actual Windows-host source with warnings-as-errors and executes `--8l1-authority-self-test`; it separately runs **accepted** 8B/8C JS suites plus strict Rust bridge/worker tests on Windows and Ubuntu. Passing JS suite alone never proves the C# side effect.
- `probes/8l1/run-native.ps1` compares source SHA, every packaged file hash, and uses a new isolated D: output. Physical `-VerifyRestart -CrashProbe -ConsentProbe -ProfileActionsProbe` is opt-in and has **no accepted source-matched owner receipt yet**.
- Generation 3 closes a native concurrency gap by leasing each affected profile from BEFORE its modal approval THROUGH navigation/Rust transfer/fresh WebView2 rebind. A second profile action on any leased profile is rejected atomically, and permission requests on leased profiles deny before the owner dialog. This is the same compiled C# helper used by runtime and its self-test.
- **Independent reviewer decision still required.** Contractual deviations remain: no direct JS controller callbacks, non-generalized production provider sign-in/origin allowlist, no single distributed atomic commit across Rust and C#, and physical browser behavior NOT_RUN. If reviewer requires direct JS integration or stronger distributed transactional semantics for #114, leave **Changes Required** and implement those on a follow-up head before cloud merge.
- Never claim `native8L1Accepted`, signed-in 7U1, production 15HOST, or whole-product performance PASS from this matrix, hosted CI or synthetic receipts.

## Accepted scope split / executable origin-fence regression (generation 4)

- **8L1-HOST cloud** is explicitly a **synthetic-only privileged native product-owned WebView2 host and physical-qualifier runner**, not general provider sign-in. Accepted 8B and 8C *JS contracts* remain independent definitions; a direct JS runtime implementation is not asserted.
- The native `EligibleSyntheticNavigation(providerId, requestedOrigin, binding)` is used in real `ApproveSyntheticSignIn` before the modal and requires exact `synthetic` provider, exact `https://synthetic.cos.test` origin and current native binding's origin. Windows `--8l1-authority-self-test` exercises positive admission plus negative unsupported provider IDs, HTTP, userinfo, origin path/trailing slash, spoofed subdomain and mismatched current binding. `StartUrl` is still the isolated virtual-host fixture; this test DOES NOT launch external provider sign-in.
- The proper **full production provider/origin sign-in** task is [8P-HOST #123](https://github.com/KaisAbiyyi/chat-on-steroids-on-steroids/issues/123) (separate dependency before real 7U1). Explicit owner sign-in and observe-only proof remain [7U1 #91](https://github.com/KaisAbiyyi/chat-on-steroids-on-steroids/issues/91). The physical synthetic 8L1 test stays separate and **NOT_RUN**, `native8L1Accepted=false`.
- An independent reviewer must accept **the bounded #114 cloud deliverable**, not assert full 8B/8C runtime equivalence to the generalized contract. Prior review finding is resolved by an enforceable scope split, **not** by claiming unsupported functionality. Do not merge without new final-HEAD CI and reviewer sign-off.
