Tracking: [issue #123](https://github.com/KaisAbiyyi/chat-on-steroids-on-steroids/issues/123). Baseline: merged 8L1-HOST PR #120, main `aeb6fa886f84ebb0215a88aa8111c4ce9f52d4cd`.

## Native gate implemented

- `apps/windows-host/Native8P.cs` introduces a host-only maximum-16 provider ID + exact HTTPS origin allowlist with explicit, separately configured redirect origins. Canonical origin syntax, duplicate IDs, subdomain impersonation, userinfo, query/fragment credentials, custom schemes, wrong-provider redirect, malformed config and unlisted providers fail closed.
- The isolated product Windows host `--8p --8p-config <D:\...json> --8p-provider <id>` requires a native Yes/No consent (default No), creates a fresh D: WebView2 browser profile, navigates only to the selected provider's bare landing origin and checks each real `NavigationStarting` event. Popups and all permission requests are denied and not saved. A navigation invalidates any prior document authority.
- No renderer/extension argument can configure the allowlist or grant consent. The user must supply the native-owned policy file; CI uses the synthetic inline selftest only.
- The old 8L1 synthetic host remains the only code path that binds the verified 7L2 Rust/MV3 worker. A production provider landing page **cannot** call `BindAsync`, `ObserveAsync`, ledger, CDP, or permissions. It cannot inherit synthetic authority simply because the HTTPS origin is accepted.
- `.github/workflows/8p-host.yml` builds native Windows host/Rust child, executes compiled C# allowlist and synthetic regression suites, runs Rust and JS 8B/8C tests on Windows and Ubuntu, and publishes a source-SHA and all-loadable-binary SHA256 verified Windows bundle. The physical script `probes/8p/run-native.ps1` requires the exact matching D: checkout/artifact and fresh isolated output. No credentials, navigation URLs or account data are added to the receipt.

## Explicit remaining 8P-HOST requirements (NOT ACCEPTED)

1. Production MV3 installed extension + Rust bootstrap must be native-attested **after each** provider redirect/document generation, not only synthetic `StartUrl`. No production signed-in observation, host/worker equivalence or capability grants yet.
2. `probes/8p/production-contract.test.mjs` adds hosted Windows/Ubuntu differential vectors against accepted 8B/8C controller contracts: host proof only, opt-in sign-in start, session-only atomic handoff, replay/partition theft denial, navigation rebind, foreign/stale native lifecycle proof and default-deny permissions. These callbacks are **synthetic privileged host fakes**; full production C#–Rust–MV3 differential integration, real redirect/reentrant consent and live partition evidence still require dedicated executable proof. This bounded C# navigation gate does not prove them.
3. OAuth authorization-code **request** URLs with strict PKCE/S256, one host-configured HTTPS redirect URI, a bounded state value, nonduplicate approved keys, and no fragment may navigate within the allowlist. Credential-bearing **callback** queries (`code`, `access_token`, `id_token`, `refresh_token`, etc.) still fail closed; actual one-use native callback binding and full OAuth lifecycle remain NOT_ACCEPTED. Real provider login is not proven. Compiled C# policy selftests include positive PKCE request and negative callback, forged redirect, duplicate state, unsupported flow and short state.
4. Independent exact-HEAD security review and ALL required CI workflows PASS must precede merge. 7U1 owner consented signed-in observe-only gate and physical 8L1 are separate **NOT_RUN**. No full product/performance claim.
