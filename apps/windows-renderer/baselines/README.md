Windows CI uses GitHub authenticated REST to obtain the *original, pinned
archive and the checker comment*; it verifies approval author, exact surfaces,
original archive digest, per-image SHA-256 and source-bound receipts. Approved
images are extracted under RUNNER_TEMP, outside the current source/workspace
capture directory. Current native Rust -> C# WebView2 captures must then match
**byte-for-byte**, failing on any unexpected rendering/PNG drift, missing
image/receipt, mismatched source, forged approval, or expired artifact. CI
writes a separate regression receipt. Candidate receipts remain
approvedGolden=false and productAccepted=false; successful comparison is not
an independent reviewer approval of new product scope.

**Retention caveat:** Actions artifacts are immutable while retained but
**not permanent**. When GitHub expires artifact 12739726480, this gate must
fail closed. Any migration to a permanent Git/release baseline requires
independent checker reauthorization, exact original hashes, and a separately
reviewed PR. Never silently regenerate or self-approve references.

**Trusted release boundary:** design-level Sigstore verification is not enough
without protected main issuer. GitHub branch API reports main
protected=false and repository rulesets=[] as of 2026-10-27; classic branch
protection endpoint is 403 to the installed GitHub App. Owner must enable
effective main branch rules with no unauthorized bypass, mandatory PR reviews
and relevant required checks, restrict workflow and attestation publisher
modification, and provide readable settings evidence. Authenticated,
properly protected main release attestation is post-merge/pre-deployment.
Do not treat PR candidate attestation as release approval.
